Mathematical Mappings

Wiedemann 99 * SUMO Krauss * IDM - All share the same kinematic base sqrt(a*b)

Wiedemann 99 (VISSIM)

d = CC0 + v*tau*safety + v*(v-vl)/(2*sqrt(a*b))*safety

Krauss (SUMO)

s* = minGap + v*tau - v*(vl-v)/(2*sqrt(a*b))

TTC (Conflict Detection)

TTC = gap / (v_follower - v_leader)

Emergency Braking

a = v^2 / (2*gap)

Methodology & Analytical Derivations

Transparent documentation of how physical vehicle dimensions and kinematic constants are converted client-side into Weighted Average Reaction Time (τavg) and Estimated Roadway Capacity (C)

1

Effective Space per Vehicle in Queue

Each vehicle occupies a physical space in the queue equal to its body length plus its safe standstill gap (CC0). This is the minimum bumper-to-bumper distance at zero speed:

Effective_Spacei = Li + CC0i    |   where L = vehicle length (m), CC0 = minGap (m)

Example: Mlaiky → 4.5m + 1.8m = 6.3m effective space. Naql-Taqeel → 16.5m + 3.5m = 20.0m effective space.

2

Dynamic Space Headway at Speed

At operational speed v, the dynamic space headway is a direct function of the vehicle's reaction time (τ) and safety factor. The browser computes:

Dynamic_Headwayi = Li + CC0i + v · τi · safetyi + v² / (2√(a·b)) · safetyi

This is the Wiedemann 99 safe distance formula, computed per-vehicle for the Cairo Ring Road free-flow speed (v = 80 km/h = 22.22 m/s).

3

Weighted Fleet Averages (τavg)

When the MPR slider is adjusted, the client-side engine computes a weighted average across the heterogeneous fleet. For each parameter p:

pavg = Σi=1..9 (MPRL0,i · pi) + Σj=1..5 (MPRAV,j · pj)

The L0 human-driven share is distributed proportionally across 9 vehicle types (Mlaiky 30%, Microbus 20%, etc.). The AV share is split equally across 5 SAE levels.

4

Estimated Roadway Capacity (C)

The browser computes the capacity metric (veh/hr/lane) using a weighted macro-mapping derived from individual micro-parameters. The formula explicitly incorporates physical vehicle length and gap:

C = 3600 / ( Σi=1..n(MPRi · τi) + (&overline;L + &overline;Gap) / v )

Where:

  • &overline;L = dynamic weighted fleet average length (m), computed from FLEET[i].len × MPR[i]
  • &overline;Gap = weighted safe buffer distance (m) = Σ(MPRi · CC0i)
  • v = operational free-flow speed = 80 km/h (22.22 m/s) for Cairo Ring Road
  • τi = per-vehicle reaction time (s), from FLEET[i].cf.reaction

At MPR = 0% (all human): C ≈ 1800 veh/hr/lane. At MPR = 100% (all AV): C ≈ 3200 veh/hr/lane. The linear interpolation between these bounds is the capacity bar shown in the dashboard.

Software Integration Guides

Step-by-step instructions to deploy our pre-calibrated fleets into your simulation environment.

Deploying Fleet into PTV VISSIM

1

Open Your Base Network

Launch PTV VISSIM and open your existing base network layout file (.inpx) containing your road geometry, signal controllers, and desired traffic demand.

2

Read Additional Network

Navigate to File → Read Additional → Network from the top menu bar. This command allows you to merge vehicle type definitions without overwriting your existing road links, connectors, or signal plans.

3

Select Fleet File

Browse to and select our downloaded /fleets/custom_egypt_fleet.inpx file. Confirm the import dialog — VISSIM will inject the Wiedemann 99 parameters (CC0-CC9, OP0-OP16) for all Egyptian vehicle types into your vehicle type library.

Verify & Run

Open the vehicle type list to confirm the new types appear. Assign them to your desired vehicle inputs. Run the simulation and verify that the aggressive Egyptian driving behavior matches expected calibrations.

Deploying Fleet into SUMO

1

Place Route File

Copy the downloaded /fleets/egypt_sumo_fleet.rou.xml file into your core SUMO project folder (the same directory that contains your .sumocfg and network files).

2

Edit Master Config

Open your master configuration file (.sumocfg) in a text editor. Inside the <input> tag, nest the following route-file reference:
<route-files value="egypt_sumo_fleet.rou.xml"/>

3

Add Additional Files (Optional)

If using bus stops for microbus dwell-time simulation, add the additional file reference:
<additional-files value="egypt_sumo_fleet.rou.xml"/>

Launch & Validate

Run via sumo-gui -c your_config.sumocfg or through Python/TraCI. Open SUMO-GUI to visually confirm vehicle colors, types, and lane-changing behavior match the calibrated Egyptian fleet profiles.

Deploying Fleet into Aimsun Next

1

Open Your Aimsun Model

Launch Aimsun Next and open your existing micro-simulation model (.ang or .aprx). Ensure your network geometry and demand are properly defined.

2

Register API Extension

Navigate to Project → Properties → API Extension. In the Python/ANSDK script field, browse to and register our /scripts/vissim_sae_override.py script. This will execute dynamic vehicle kinematic overrides on each simulation time step.

3

Configure Vehicle Types

Open the Vehicle Types editor within Aimsun. Create or import vehicle types matching the profiles in our script (Egyptian Microbus, Mlaiky, Naql, AV L2, AV L4-5). Link each type to the corresponding IDM car-following parameters defined in the override script.

Run & Inspect

Start the micro-simulation. The registered Python script will dynamically apply TTC-based conflict resolution, override vehicle kinematics during cut-in events, and log calibration data to the output. Check the Aimsun output console for parameter application confirmations.
